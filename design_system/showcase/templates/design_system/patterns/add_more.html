{% extends "design_system/base.html" %} {% block ds_title %} Add More - PLOS Design System {% endblock ds_title %} {% block ds_content %} {% component "plos_heading" level=1 %}Add More{% endcomponent %} {% component "plos_text_box" %} plos_add_more shows a list of repeating items, one accordion section per item, that people can add to and delete from. It works without JavaScript. Without HTMX, the add and delete buttons submit the form and the page reloads. With HTMX, the same buttons post the form to htmx_url (usually the page's own URL) and replace only the list, <div id="{name}-add-more">, so the page doesn't reload. The same view and template handle both. {% endcomponent %} {% component "plos_text_box" %} The add and delete buttons belong to this pattern, not to plos_button. Their styles (a tinted add button and a red, underlined delete link) only apply inside add more. The delete link only shows when there is more than one item, and the add button goes away once the list reaches max_items. {% endcomponent %}

{% component "plos_heading" level=2 %}How to use it{% endcomponent %} {% component "plos_text_box" %} A page using add more needs a template and a view. The component shows the list. The view decides what add, delete and save do. The example above is built this way. {% endcomponent %} {% component "plos_heading" level=3 %}Template{% endcomponent %} {% component "plos_text_box" %} Put the component inside your own form, with your own submit button. Fill the item slot with the fields for one item. Set each field's name and id to {field_id}_{slot_data.index} so posted values and error links match the right item. {% endcomponent %} {% filter force_escape %}{% verbatim %}

{% endverbatim %}{% endfilter %} {% component "plos_text_box" %} Inside the fill, slot_data gives you: {% endcomponent %}
  • index: the item's position as a string, starting at 0, for names and ids
  • value: this item's entry from values (a string, or a dict for items with several fields)
  • errors: this item's error messages by field, for example slot_data.errors.patent
  • autofocus: true when this item's first field should take focus after an add or delete; pass it to that field only
{% component "plos_heading" level=3 %}View{% endcomponent %} {% component "plos_text_box" %} Every button in the form posts to the same view. If patents__action is set, someone pressed add or delete: apply it and render the page again, without validating or saving. If not, they pressed your submit button: validate and save as usual. Always render the whole page. With HTMX, the component takes the list and the error summary from the response. The helpers in plos_django_components.components.patterns.add_more.logic handle the list for you. {% endcomponent %} {% filter force_escape %}{% verbatim %}from django.shortcuts import redirect, render from plos_django_components.components.patterns.add_more.logic import ( apply_add_or_delete, collapsed_after_add_or_delete, error_summary_entries, posted_count, ) MAX_PATENTS = 10 def patents_page(request): patents = [""] # Or the saved patents errors = None collapsed = [] action = "" if request.method == "POST": count = posted_count(request.POST, "patents", MAX_PATENTS) patents = [request.POST.get(f"patent_{i}", "") for i in range(count)] action = request.POST.get("patents__action", "") if action: # Add or delete: show the change, don't validate or save patents = apply_add_or_delete(patents, action, MAX_PATENTS) collapsed = collapsed_after_add_or_delete(request.POST, "patents", action) else: # Save: validate each item errors = [ None if patent.strip() else [{"field_id": "patent", "message": "Enter a patent number"}] for patent in patents ] if not any(errors): save_patents(patents) return redirect("next_page") return render(request, "patents.html", { "patents": patents, "errors": errors, "error_summary": error_summary_entries(errors, "patent"), "collapsed": collapsed, "last_action": action, }){% endverbatim %}{% endfilter %} {% component "plos_text_box" %} apply_add_or_delete never returns an empty list: deleting the last item leaves one blank item. For items with several fields, read each item into a dict and pass an empty dict with the same keys as empty_item. errors has one entry per item: None when the item is valid, or a list of {"field_id": ..., "message": ...} dicts, where field_id is the field id without the index. {% endcomponent %} {% component "plos_heading" level=3 %}Error summary{% endcomponent %} {% component "plos_text_box" %} The page owns the error summary, so a form has one summary for all its fields. The component only shows errors inline. error_summary_entries turns the add more errors into summary entries such as "Patent 2: Enter a patent number". Add them to the page's other entries. Wrap the summary in an element that is always rendered and pass its id as error_summary_id. With HTMX, add and delete then refresh that element too, so the summary never links to items that have moved or gone. {% endcomponent %} {% component "plos_heading" level=3 %}JavaScript{% endcomponent %} {% component "plos_text_box" %} Load HTMX on the page to update the list without a reload. The component brings its own script, which keeps collapsed items collapsed after an add or delete. Without HTMX, or with JavaScript off, every button submits the form and the page reloads. {% endcomponent %} {% component "plos_heading" level=3 %}Posted fields{% endcomponent %}
Field Contains
{name}__count How many items the form holds. Read it with posted_count, which keeps it between 1 and max_items.
{name}__action add or delete__N (N counts from 0) when someone presses add or delete. Your submit button doesn't send it.
{name}__collapsed The indexes of collapsed items, such as 0,2. Only sent with HTMX requests. Read it with collapsed_after_add_or_delete.
{field}_{index} Your own fields, named in the slot fill.
{% component "plos_heading" level=3 %}Parameters{% endcomponent %}
Name Description Default
name Prefix for the posted fields and the list's id. Required.
item_label What one item is called, used in headings ("Patent 1") and button labels. Required.
values One entry per item. Use [""] for one empty item. Required.
max_items The most items allowed. The add button goes away at this number. Required.
htmx_url Where add and delete post with HTMX, usually the page's own URL. Required.
errors Per-item errors, shown inline. Items with errors stay expanded. None
collapsed Indexes of items to render collapsed, from collapsed_after_add_or_delete. None
last_action The posted {name}__action, so focus moves to the new item after an add, or to the next item (or the add button) after a delete. None
error_summary_id Id of the element that wraps the page's error summary. HTMX refreshes it on each add and delete. None
item_label_plural Used in the hint "You can add 3 more patents". item_label + "s"
add_label, delete_label The start of each button label. Add is followed by the item label ("Add another patent"). Delete is followed by the item label and number ("Delete patent 2"). "Add another", "Delete"
add_icon, delete_icon Icon classes for the buttons. The add_item and delete_item icon settings
add_icon_size, delete_icon_size plos_icon sizes for the button icons. "xs", "md"
